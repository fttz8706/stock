# 安全修复与迁移说明

本分支修复安全审查发现的接口、缓存、批量任务、交易热更新及部署问题。不会自动迁移已有数据库，也不会启动券商交易。

## 新部署

建议 Python 3.11，与容器环境一致。设置以下环境变量（密码使用各自独立的随机值，不提交到 Git）：

| 变量 | 用途 |
| --- | --- |
| `INSTOCK_WEB_USER` | 网页访问账号 |
| `INSTOCK_WEB_PASSWORD` | 网页访问密码，必须设置 |
| `db_user` | 原生部署数据库账号，默认 `instock` |
| `db_password` | 原生部署数据库密码，必须设置 |
| `INSTOCK_DB_PASSWORD` | Compose 中的应用数据库密码 |
| `INSTOCK_DB_ROOT_PASSWORD` | Compose 中的数据库管理员密码 |
| `INSTOCK_COOKIE_SECRET` | 可选的 Cookie 签名密钥；不设置时每次启动随机生成 |

原生部署先使用管理员创建 `instockdb` 和专用账号，仅授权该数据库的读写、建表、索引等权限。运行任务会初始化关注表。不要让应用使用数据库 root 账号。

从仓库根目录运行 `docker compose -f docker/docker-compose.yml up -d --build`，使用本分支源码构建镜像。也可以运行 `sh docker/build.sh` 仅构建镜像；构建脚本不再自动推送远端镜像。

网页默认只对本机开放。打开 `http://localhost:9988` 后，浏览器弹出账号密码输入框。若需要远程访问，请通过配置了 HTTPS 的反向代理，并保留认证；HTTP Basic 本身不加密密码，不应通过明文公网传输。原生服务地址可用 `INSTOCK_WEB_HOST` 配置，Compose 在容器内监听全部接口，但只将宿主机的 `127.0.0.1:9988` 发布出来。Supervisor 仅保留 Unix 管理套接字。

代理、东方财富 Cookie 和券商账号文件不包含在镜像中。需要时以只读挂载方式提供 `instock/config/proxy.txt`、`instock/config/eastmoney_cookie.txt`。Cookie 也可通过 `EAST_MONEY_COOKIE` 设置。已有 Git 跟踪的示例配置不会因为 `.gitignore` 自动取消跟踪，请不要把真实凭据写回这些受跟踪文件。

## 已有数据库迁移

旧配置把宿主机目录挂到了 `/var/lib/instockdb`，实际数据可能在旧容器 `/var/lib/mysql` 对应的匿名卷中。**不要直接删除旧容器或卷，也不要认为 `/data/mariadb/data` 已经包含真实数据。**

1. 停止写入任务，检查旧容器的挂载信息与 MariaDB 版本。
2. 用现有数据库账号将 `instockdb` 完整逻辑导出，验证备份可读，并保留原容器和数据卷以便回滚。
3. 在新的空数据目录初始化 MariaDB 11.4。不要把不同主版本的数据文件直接交给新镜像启动。
4. 将备份导入，创建专用 `instock` 账号并授予 `instockdb` 范围的权限。核对表数、行数和关键日期后再切换应用。
5. 新配置将 `/data/mariadb/data` 挂到实际目录 `/var/lib/mysql`。如果已有有效数据目录，初始化环境变量不会重设旧密码；需通过数据库管理命令调整账号。

以上操作需要按实际部署执行，本次代码修复没有触碰用户数据库。

## 行为变化

- 关注接口改为 POST，需要登录及 XSRF 校验；前端已同步修改。重复关注使用幂等写入，数据库错误返回非成功状态。
- 所有股票代码限定六位数字；日期验证格式及有效性；名称在图表 HTML 中转义；相关 SQL 使用参数绑定。
- 缓存使用原子替换的压缩 JSON，旧 pickle 不再读取。首次运行会重新抓取；缓存键包含开始日期、结束日期和复权类型，跨日失效；关闭缓存时既不读也不写。可在停机后清理旧 pickle 文件回收空间。
- 日期相关数据不再使用忽略参数的全局单例，优先保证批量计算的隔离和正确性。多策略同时计算时，首次下载量可能增加；磁盘缓存继续复用。
- 总任务恢复指标、K 线形态、策略和回测，并等待计算阶段完成后回测。部分旧模块仍将单股票或外部数据源失败记入日志并继续，任务完成不意味着上游所有股票均已成功采集。
- 东方财富、同花顺请求切换为 HTTPS。东方财富 Cookie 按实际键值解析，并仅发往其域名下的 HTTPS 地址，拒绝重定向。外部站点可用性仍取决于数据提供方。
- 通达信抢筹源使用非标准端口的 HTTP，默认停用该数据源，不静默降级。确认接受明文行情风险后，可显式设置 `INSTOCK_ALLOW_INSECURE_TDX=1`；Compose 使用者须自行将该变量传入容器。
- 交易服务默认关闭策略热更新。手动开启时会清理旧实例和定时事件，旧事件监听即使已经被取出也不再执行；事件串行处理，单个策略异常不终止事件引擎。此修复不提供券商层面的全局下单去重，也不将价格涨跌统计升级为含手续费、滑点及成交模拟的完整回测。

## 回归测试

使用独立 Python 3.11 环境：

```sh
python -m pip install -r requirements-test.txt
python -m pytest -q tests
```

测试使用模拟行情、数据库和券商模块；网页测试只监听临时本机端口。覆盖身份验证、XSRF、写入异常、输入转义、缓存绕过/范围/损坏/过期/路径限制、日期隔离、Cookie 发送范围、SQL 参数化、重复热更新、任务阶段顺序与失败传播。
